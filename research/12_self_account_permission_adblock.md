# 自己账号：权限最小化与去广告实操结论（含对测试账号结论的修正）

日期：2026-09-26

## 一句话结论

闪动校园Pro 的「阳光跑 → 开始跑步」会检查一组「必要权限」，其中**无障碍服务和悬浮窗不是跑步本身需要的权限**，而是 App 用于「自动改系统设置 + 推优惠广告」和「弹广告 + 熄屏续记轨迹」的手段。真正跑步只需要：定位、身体传感器/活动识别、相机、麦克风。

## 关键事实

「开始跑步」弹窗里的「必要权限」实际是四项，App 把它们打包成一张清单：

| App 说的 | 实际作用 | 跑步是否需要 |
|---|---|---|
| 辅助模式（无障碍 ShopHelperService） | 自动改系统设置、推「优惠和福利提示」广告 | 否 |
| 悬浮窗（SYSTEM_ALERT_WINDOW） | 弹广告、熄屏后续记轨迹 | 否 |
| 后台运行 + 自启动 | HONOR 后台定位 / 防误杀 | 是（系统级） |
| 精准定位（后台定位） | 熄屏 / 切后台继续记 GPS | 是 |

「后台保护」按钮的 resource-id 是 `btn_auto_open_accessibility`，证明这一项是通过无障碍服务去自动配置 HONOR 的「应用启动管理」，不是跑步功能本身。

## 最终状态（2026-09-26）

- 无障碍服务：关闭（`accessibility_enabled=0`，服务列表空）
- 悬浮窗：`SYSTEM_ALERT_WINDOW=ignore`
- 定位：前台 + 后台允许
- 身体传感器 / 活动识别：允许
- 相机、麦克风：前台允许
- 后台运行：`RUN_IN_BACKGROUND` / `RUN_ANY_IN_BACKGROUND` 默认 allow
- 电池优化白名单：`deviceidle whitelist` 已含本 App
- Private DNS：off
- 去广告：AdGuard 本地 VPN 在线（`sessionId=AdGuard`）

## 实测

关闭无障碍和悬浮窗后，点「开始跑步」不再被「必要权限未开启」拦截，正常进入「新版说明 → 跑最低 2.4km / 跑更多公里」。前提是先把「后台保护/自启动 + 电池白名单」通过 App 的一键流程配置过一次（系统设置落盘后，无障碍即可关掉）。

## 对测试账号报告（04_permission_tests.md）的修正

原报告把「无障碍」标为可关闭、「悬浮窗」标为可限制 ignore，结论本身没错，但漏了前提：那只在「后台保护/自启动 + 电池白名单」已经配置落盘、且跑步时保持前台/常亮时成立。对一个全新账号（未走一键流程）直接关掉这两项，会在点「开始跑步」时被「必要权限」弹窗拦截。

## 边界与提示

- 关掉无障碍 + 悬浮窗后，跑步时切后台 / 熄屏，轨迹连续性可能不如开着它们时，属 App 自身续命机制。
- 「优惠和福利提示」可在 App 内设置里单独关闭，不影响跑步。
